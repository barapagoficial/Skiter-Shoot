# AGENTS.md

Electron FPS "Skiter". Single-page game: almost everything lives inline in `index.html` (~410 KB); `vendor/` (three.module.js + addons) is the only 3rd-party code. No README, no test framework. Everything below is hard-won context; follow it to avoid the traps.

## Architecture (critical)
`index.html` contains one classic script plus TWO `<script type="module">` scripts (plus an importmap pinning `three`):

1. **Classic wrapper** — shop/inventory/UI (e.g. `ddRender`, `ddShop`, `ddSaveShop`, `ddSetCoins`, `ddConfirm`, buy handlers). It is wrapped in an IIFE, so **its functions are NOT globals**. Game code (module) cannot call `ddShop()`/`ddSaveShop()`.
2. **Game modules** — menus, weapons, secret-code handler (`ddBindCode`), `ddBuildGun`, `ddAcidGun`, `ddPaintAim`. Module-scoped functions are **not reachable from the page console or Playwright `page.evaluate`**; only `window.__dd*` props are shared (`__ddGoldOn`, `__ddAcidOn`, `__ddBurnFor`, `__ddGoldMat`, `__game`).

Cross-boundary rule: if module code needs classic-owned state, read/write `localStorage` directly. Real bug hit: `ddTutuClear` (module) called classic `ddShop()` → silent `ReferenceError` (empty try/catch hid it). Use `window.__dd*` or `localStorage` keys only.

## Commands (exact)
- Run locally: `npm start` (Electron), or `python -m http.server 8099` for headless browser testing.
- Build: `npm run dist` → `dist\Skiter-Portable.exe`. **Close all running `Skiter.exe` processes first** — they lock `dist` (fails on `d3dcompiler_47.dll`):
  `Get-Process -Name Skiter | Stop-Process -Force`
- Path has spaces (`...\Skiter Shoot\`): always quote paths.
